<Section title="What it will not do" lead="It is a tool for one operator and one host. Better to know now.">
<ul class="grid gap-3 sm:grid-cols-2">
  <li>It does not run without a git repository of compose files checked out on the host and pushed to an https remote. There is no mode that edits files in place.</li>
  <li>It does not manage more than one Docker host.</li>
  <li>It does not update itself. You upgrade shipshape by hand, on purpose.</li>
  <li>It does not open pull requests. Changes land on your branch; holds are how you keep the say.</li>
  <li>It does not watch images in private registries, except on Docker Hub with your Docker Hub login.</li>
  <li>It does not use ssh remotes.</li>
  <li>It does not judge how risky a version looks. Verification, the soak and rollback carry that.</li>
  <li>It is not open source. It is source-available under the Functional Source License; each release becomes Apache-2.0 two years after it ships.</li>
</ul>
</Section>

## Compared with what you may run now

| | Notices new tags | Reads release notes | Changes land in git | Deploys and verifies | Rolls back |
|---|---|---|---|---|---|
| shipshape | yes | yes, with a model | merge commit | yes | yes, once, inside the window |
| Watchtower | yes | no | no | restarts the container | no |
| What's Up Docker | yes | no | no | optional triggers | no |
| Diun | yes | no | no | no (notifies) | no |
| Renovate | yes | from the image's source label | pull request | no | no |
